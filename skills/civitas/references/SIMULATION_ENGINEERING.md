# From interesting story to auditable experiment

## Ask why a simulation is needed

Simulation is appropriate when micro interactions, constraints, timescales or nonlinear feedback are central, and a simpler descriptive analysis cannot answer the question. A story generated by an LLM, an aggregate model, an ABM, and an empirical forecast are four different products.

## ODD documentation protocol

A research grounded starting point is ODD (Overview, Design concepts and Details), updated in 2020. Describe:

1. Purpose and empirical patterns sought.
2. State variables, entities and scales.
3. Process overview and action ordering.
4. Design concepts: emergence, adaptation, objectives, learning, sensing, interactions, randomness, collectives and observation.
5. Initialization and distributions.
6. Input data and provenance.
7. Submodels, equations, parameters, and algorithms.

Add a separate **Model Validity** section explaining which mechanisms are observationally supported, how parameters were set, how the design was tested, and the domain of intended use. Source: https://www.usgs.gov/publications/odd-protocol-describing-agent-based-and-other-simulation-models-a-second-update

## Experiment protocol

- Define question and hypothesis prior to running.
- Fix an observable metric and measurement window.
- Compare treatment and baseline with **matched random seeds** when possible.
- Run multiple seeds and report variation; do not cherry pick attractive runs.
- Vary plausible parameters, initial states and update order.
- Examine edge cases, constraint violations, outcomes for less powerful groups, and tail events.
- Keep model code, environment version, parameters, seeds, timestamp, and run output.
- Evaluate against withheld observations if real world prediction is intended.
- State which interventions are model assumptions, not tested real policies.

## Model validation categories

- **Verification:** Is the implementation faithful to its specified rules?
- **Internal validity:** Could an unmodeled mechanism explain the outcome even within the chosen question?
- **Empirical validity:** Do independent observations support relevant outputs?
- **Sensitivity:** Do conclusions collapse after small plausible parameter changes?
- **Robustness:** Do other models or update schedules yield compatible implications?
- **Generalization:** Are conclusions transferable across populations, place and time?
- **Decision validity:** Would following the conclusion improve real decisions under known constraints?

## Three levels of fidelity

**Level 0, thought experiment:** verbal scenarios only. Appropriate for early exploration.

**Level 1, seeded stylized model:** explicit accounts, stochastic shocks, invariants and tests. All civlab models (`scripts/civitas.py`) and the original aggregate model (`scripts/civitas_sim.py`) operate here. See SIMULATORS.md.

**Level 2, research model:** empirically bounded parameters, agent heterogeneity where required, defensible causal structure, holdout observations, sensitivity analysis, replication and external peer review. Use a suitable platform such as Mesa or Concordia and never assume that LLM agent realism equals scientific validation.

## Bundled simulator contract

civlab (`python scripts/civitas.py`) provides eight seeded, validated, stdlib-only models plus forecasting and sensitivity tools; the original aggregate settlements model (`scripts/civitas_sim.py`, `--config --seed --runs --compare --output --csv`) is preserved unchanged. Every result carries an epistemic envelope. Model cards: SIMULATORS.md.

## Experiment checklist (civlab)

1. State the hypothesis about the model before running.
2. Baseline ≥ 10 seeds; report mean and p05-p95, not a single run.
3. Interventions via `compare` (matched seeds, paired deltas).
4. `sensitivity --method morris` on parameters that carry the conclusion; flag high sigma (interactions).
5. Check update-order and network-type robustness where relevant (`--set graph=...`).
6. Invariants: ledgers, bounds (tests in `tests/`).
7. Write the ODD summary and the disclosure block (EVIDENCE_VALIDATION.md).

## Common false claims to avoid

"Our 1,000 simulated citizens prove a new policy works." No.

"A plausible AI agent behaves like a representative person." Not established.

"Across 200 random seeds the forecast is 92 percent certain." Only a conditional distribution under one toy model.

"Our agent learned to cooperate." Could be scripted, prompted or a measurement artifact; analyze causation and competing explanations.
